# Phase 3 Core Algorithms Implementation Plan

> Execute inline with test-driven development. Preserve the supplied Phase 3 brief and the Phase 1–2 infrastructure. No commits, pushes, deployment, or Phase 4 UI work.

**Goal:** Six correct generator algorithms, consistent metadata and registry integration, verified with the existing playback controller.

**Architecture:** Keep `createSnapshot` as the only snapshot creation mechanism. A small algorithm helper validates the established 48-integer domain and creates snapshots with default highlights, cumulative metrics, mapped one-based pseudocode lines, status, result, and optional algorithm-specific metadata. All execution remains independent of React and timing.

**Tech stack:** Existing JavaScript, Vitest, Vite, React. No new dependencies.

## Tasks

1. **Sorting generators and snapshot metadata**
   - Create `src/algorithms/{execution,bubbleSort,insertionSort,mergeSort,quickSort}.js` and `tests/sorting.test.js`.
   - Write failing tests for known outputs, empty/single/duplicate/negative/zero/48-element cases, seeded numeric-sort properties, immutable snapshots, pseudocode mapping, and exact metrics.
   - Implement early-exit Bubble; shift-based Insertion; recursive buffered Merge; last-pivot Lomuto Quick. Exclude self-swaps; count main-array writes independently of merge buffer writes.
   - Initial states use `status: ready`; final states use `status: complete` and `result`. Every snapshot includes `metrics.steps` (one-based emitted frame count). Metadata and pointers are deep copied by the existing snapshot utility.
   - Run targeted and full tests.
2. **Searching and dynamic programming**
   - Create `src/algorithms/{binarySearch,kadane}.js` and `tests/searchAndKadane.test.js`.
   - Write failing known-result tests plus independent leftmost-search and quadratic Kadane oracles. Test unsorted rejection through controller.error, bounds and target validation, all-negative input, zeros, duplicate optima, and empty input.
   - Binary Search returns leftmost occurrence, rejects unsorted input without sorting; counts one three-way key comparison per iteration. Kadane ties favor earliest start then earliest end; empty result is `{sum:0,start:null,end:null,subarray:[]}`.
   - Run targeted and full tests.
3. **Registry and playback integration**
   - Register definitions in `src/engine/algorithmRegistry.js`; create `tests/algorithmPlayback.test.js`.
   - Entries expose id, name, category, generate, inputRequirements, pseudocode, complexity, supportedMetrics.
   - Verify real generators load, step, rewind, seek, restart, terminate, cancel, switch input/algorithm, and stay within default cache limits.
   - Test exact cached navigation after cache overflow. If needed, minimally move cached navigation ahead of the generation-error guard; no eviction or deterministic regeneration subsystem.
   - Leave visual UI unchanged; registry and controller tests prove executable integration.
4. **Documentation and final checks**
   - Update README and verification report with policies, metadata, metrics, complexity, current scope and Phase 4 recommendations.
   - Run `npm test -- --run`, `npm run lint`, `npm run build`. Preserve all existing tests. No browser visual-test claim.

## Review focus

- Input or options mutation during a suspended generator must not mutate a previously emitted snapshot.
- Pointers may use explicitly documented boundary sentinels (-1 or array.length); highlights must always be real indices.
- Temporary insertion holes and merge buffers must be reconstructable without implying invalid swaps or globally final positions.
- Bounded-cache overflow must preserve exact navigation among cached frames while blocking additional generation.
- Final snapshot completion and exhausted-iterator completion are separate controller concepts; both must remain inspectable.
